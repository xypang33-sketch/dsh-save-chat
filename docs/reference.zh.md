# 参考手册

> 这是 `dsh-save-chat` 的完整参考：文件格式、接口、设计取舍与限制。
> 快速上手请看 [README](../README.md)。

---

DSH 的「收藏此轮对话」插件：在助手回复的动作行点一下心形，就把这一轮问答存成工作区里的真实 Markdown 文件；左侧栏提供一个跨工作区、跨会话的收藏面板，点开某一条就在列表旁边渲染出这一节的 Markdown。

[English](README.md)

## 三个界面位置

| 位置 | 机制 | 行为 |
|---|---|---|
| 助手回复动作行的心形按钮 | `conversation.chat.assistant-actions` 席位 | 空心灰=未收藏，实心红=已收藏；点击立刻变色（写入在后台完成），再次点击即取消，不会重复收录 |
| 左侧栏「收藏」入口 | `sidebar.panellist` 入口 + `main` 面板 | 「工作区文件夹行（点一下折叠/展开）→ 会话（也有自己的折叠箭头）→ 每条收藏（序号 + 题目 + 时间）」；没点任何条目之前页面保持整宽；在收藏条目上**右击**可置顶 / 重命名 / 删除 |
| 列表旁的阅读区 | DSH 自己的 `MarkdownText` 渲染宿主半返回的文本 | 点某条收藏**默认只看该小节**；工具条上的「**展开全文**」切到整篇并自动滚到该小节，再点「**只看该节**」收回来。点会话名始终从文件开头读整篇，此时那个切换按钮会保持可见但置灰，并用 tooltip 说明原因。「**在文件夹中显示**」把文件路径交给宿主文件管理器定位。列表始终留在屏幕上、也不产生任何导航 |

## 依赖

- 一个 DSH 的 Web/GUI profile（插件注册的是浏览器侧界面和一组回环 HTTP 路由）。
- profile 需要提供 `sessionQuery`、`workspaceRegistry`、`webServer`，以及客户端服务 `slots`、`locale`；官方 Web bundle（`dsh-web-app`）全部具备。「在文件夹中显示」由插件自己的宿主半完成（下面路由里的 `POST /reveal`），它把路径交给会话控制器的桌面打开能力；无法打开时工具条会显示宿主给出的具体原因。
- 可选：`llm` 模型路由。没有时，收藏条目会用你自己的问题命名，而不是模型总结。

## 安装

在 DSH 的 Plugins 页面、通过 `plugin_manager` 工具，或命令行：

```sh
# 从 npm 安装
plugin_manager install_bundle "dsh-save-chat"

# 或安装本地目录
plugin_manager install_bundle "/绝对路径/dsh-save-chat"
```

包声明了 `dsh.bundle.patch`，安装时会把一行 Loader 条目插入当前 profile；浏览器半由 `exports["./client"]` 提供，不需要构建步骤。安装后刷新一次页面即可加载新的客户端 bundle。

## 收藏文件

一个会话一个文件，文件名就是会话标题，放在该会话的工作目录下：

```
<会话工作目录>/.dsh-favorites/<会话标题>.md
```

第一次收藏时创建，之后每次收藏追加一段；取消收藏只删除那一段。文件本身是唯一事实来源：心形状态、面板内容都从文件解析，没有第二份索引可以漂移。示例：

```markdown
# 创建并运行临时 Cordis 浮窗计数器插件

[//]: # "dsh-favorites:session=session-ce020ac1-a133-460e-bd37-6e3883385c13"

[//]: # "dsh-favorite:start 61ed3cd4-d01f-4cee-b59f-5fafe807eda9"
## 1. add_compare 名称冲突及动态插件受限分析
*2026-09-17 00:22*

### User

> 请创建并运行一个临时动态 Host 插件…

### assistant

我按你的要求先检查了工具注册接口和已有工具名，结论如下。

#### 1. 名称冲突：`add_compare` 已存在

…

[//]: # "dsh-favorite:end"
```

文档层级固定为：`#` 会话标题 → `##` 收藏条目 → `### User` / `### assistant` 说话人 → `####` 及更深是回复正文自己的标题。正文标题会被自动降级，永远不会和包含它的条目同级；代码块里的 `#` 不会被改动。条目标题只放 1-based 序号（`## 2. …`），收藏时间放在它下面那行小号斜体里——Markdown 没法在一行标题里混排字号，那里是唯一能让时间保持小字的位置。序号始终连续，删掉一条会自动给后面的重新编号。

插件的记账信息写成 Markdown 的**链接引用定义**（`[//]: # "…"`）：CommonMark 会把它当作定义消费掉，所以渲染出来的文档里看不到任何插件语法，而文件仍保留插件需要的一切。本包早期版本写下的段落（HTML 注释标记、标题下的说明行、单独的斜体时间行、没有序号的标题）仍能被读取和删除，并在下次写入该文件时迁移成当前形式。

## 收藏条目的名字

收藏时，宿主半用**该会话最后一次请求所用的模型路由**（会话日志里的 `request/header`）生成一个短标题，作为目录条目名和 markdown 的 `## 标题`：

- 输入是这一轮的用户输入 + 助手正文，截断到 4000 字符；输出上限 48 token，超时 8 秒（`purpose: 'session-title'`）。
- 任何失败（没有路由、没有 `llm` 服务、拒绝、超时、provider 报错）都退回**你这条消息的第一行**（截断 40 字），所以永远有名字可用。
- 标题只在点红心那一刻生成一次，读面板不会调用模型；取消再收藏会重新生成。

## 条目操作（右击菜单）

在收藏条目上右击，有三个操作，三者都直接改写那一条自己的 markdown 小节——没有第二份存储可以漂移：

- **置顶**：把该小节移到文件里所有小节之前，并在它的标记行里记下 `pinned` 字段（`[//]: # "dsh-favorite:start <messageId> … pinned"`），所以"谁被置顶"只看文件就知道。菜单随后变成**取消置顶**，只清除字段、不移动位置；之后新收藏的小节会追加在置顶项下面。
- **重命名**：替换该小节标题里的题目（序号和其它字段保持不变），在行内输入框里完成，Enter 提交、Esc 取消。
- **删除**：移除该小节。对话里的心形读的是同一个文件，所以那条随即回到未收藏状态。

## 检索 —— 你用，模型也用

同一套检索后端支撑两个入口，所以你手动搜到的，就是模型能搜到的。

- **面板里**：标题栏放的是「**收藏 / 知识库**」切换，不再是刷新按钮（进入某个视图就会重新读一次文件——你手工编辑过的收藏也因此能看到）。搜索框只搜**眼前这个列表**：收藏视图搜收藏，知识库视图搜知识库。每条命中显示标题、时间、`文件#行号` 和片段；来源看路径就知道，所以不加标签。点一下就在右侧阅读区打开该小节。
- 任意条目上的「**复制引用**」会把 `@<文件>`（DSH 自己的 mention 语法，路径含空格时自动加引号）放进剪贴板——粘到之后的对话里，模型就能读到这份记录。
- **图片与附件不再丢失**：记录里会在附件原来的位置留一行占位，例如 `_[图片：image.png · 706×94 · 5.3 KB · image/webp · sha256:7e9140cc…]_`。思考过程与工具记账仍然不进记录。
- **按大小与 mtime 缓存解析结果**：第一次读过之后，未改动的文件不再重复解析（60 个收藏文件：冷读 2.5 ms、热读 0.3 ms）。文件一改，大小或 mtime 就变，立刻重新读取；文件被删除时缓存也随之清掉。
- **知识库你自己可改**：知识库视图按**月份分组**（就是它所在的文件）列出每一条已提升的内容，右键可以**重命名**（只改副本，收藏层自己的标题不变）或**移除**。原项目已经消失、收藏行不复存在时，这也是唯一能把那份副本删掉的入口。视图上还**加粗提示**：知识库的内容 AI 可按需检索、不会自动注入对话。右侧阅读区带一个关闭按钮，点一下列表就恢复整宽。
- **给模型**：`search_knowledge`（query、`scope` = `knowledge` | `all`、`limit`）加上 `read_knowledge`（按命中 id 取回整节）。两者都是**按需**的：不搜索就完全不进上下文，没人问的库一分钱不花。工具描述里写明何时该用（用户提到"上次/之前/复用"）、何时不要用（与历史无关的新问题）、命中的是**用户自己保存的记录、可能过时或有误**，并要求引用时注明来源与日期。
- 切块是**段落级**（代码围栏绝不切开），排序因此更精确；但**一个小节只算一条命中**——同一轮里多处命中会被合并成一条并标注处数（面板显示「本节 N 处命中」），命中额度因此花在不同轮次上。每条命中只给约 400 字片段，`read_knowledge` 单次最多返回 8 KB——一次检索不可能灌满上下文。
- 排序是自写的 **BM25** + 内置分词（拉丁词整词、中日韩按二元组），**零依赖、无向量库、不写索引文件**——知识库始终是你能读、能改、能 grep 的纯 markdown。
- 已经被提升进知识库的那一轮只会出现一次（以知识库副本为准）。

## 个人知识库

这个库在三个读者都能看到的地方写着同一条规则——文件头、检索结果、工具描述：**同一主题若前后矛盾，以「原会话时间」较晚的一条为准**。命中的顺序由相关度决定；相关度并列时，按时间新的排前。

在收藏条目上右击还可以 **加入个人知识库**：把这一节复制进一个**跨项目**的个人库。两层各司其职——收藏是项目内的原始记录，知识库是你决定长期留下的东西。

- 位置：`~/.dsh/knowledge/<年-月>.md`，每月一个文件；可按 profile 覆盖：

  ```yaml
  - id: dsh-save-chat
    name: dsh-save-chat
    config:
      knowledgeDir: /你的/笔记仓库/知识库
  ```

- 每份副本在自己的标记行里带来源：`[//]: # "dsh-knowledge:start <messageId> from=<会话id> at=<ISO> source=<收藏文件>"`，正文前还有一行 `*收录 <日期> · 原会话 <时间>*`——即使原项目没了也能追溯回去。
- 复制的是**整节原文**（用户输入 + 助手回复，标题层级照旧）。
- **图片一起搬过来**：该节引用到的图片/附件会被复制进 `~/.dsh/knowledge/assets/`，md 里的路径改写成这份副本；每张图片下面还会写一句**图片摘要**（每张图一次小视觉调用，用该会话自己的模型路线）——正是这句摘要让图片之后可以**按内容**被检索，而不是只能按文件名。标记里会记 `summaries=N`；模型不可用时图片照常保留，只是没有摘要。
- **加两次只会有一条**；加入后条目行上出现 `★`，悬停显示它落在哪个知识库文件。
- **从知识库移除不会动收藏**；反过来，删除收藏也不会动知识库——两个存储互相独立。某个知识库文件被删空时会连同文件一起移除。
- `★` 状态随目录接口一起返回，所以刷新页面后依然正确。

## Token 消耗记在哪

收藏一轮只会多花一次模型调用：生成标题那一次。它的计费计数记在**该小节自己的标记行**里——

```
[//]: # "dsh-favorite:start <messageId> tokens=<input>+<output>"
```

——`input` 是整个提示词侧（未缓存 + 缓存读 + 缓存写，适配器把它们报告为互不重叠的计数），`output` 是生成的 token 数。面板会把已记录的部分累加，显示在「刷新」旁边；每条目自己的用量在该行的悬停提示里。

除此之外没有任何地方记录它。DSH 只在调用方主动落盘时持久化用量——agent loop 写 `assistant/message`——而这次调用是插件直接发起的 `ctx.llm.stream()`，所以它**不在**会话日志、不在每条消息的用量角标、也不在 DSH 遥测里。DSH 自己的会话标题生成同样如此：它记录了请求（`session/title-llm-request`），但没有记录返回的用量。加入这项记录之前收藏的小节没有计数，所以面板合计只覆盖"有记录"的收藏。

## HTTP 接口（仅回环地址）

宿主半在 `webServer` 上注册三个 exact 路由，浏览器半通过这些路由读写收藏：

```
POST /dsh-save-chat/catalog   {}                        -> { workspaces: [...] }
POST /dsh-save-chat/state     { sessionId }             -> { messageIds, filePath }
POST /dsh-save-chat/toggle    { sessionId, messageId }  -> { favorited, filePath, ... }
POST /dsh-save-chat/document  { filePath, messageId? }  -> { markdown }
POST /dsh-save-chat/favorite  { action, filePath, messageId, title?, pinned? }
POST /dsh-save-chat/reveal    { filePath }                        -> { revealed: true }
POST /dsh-save-chat/knowledge { action: 'add' | 'remove', filePath?, messageId }
POST /dsh-save-chat/search    { query, scope?, limit? }            -> { hits: [...] }
```

`favorite` 执行一个行操作：`pin` / `unpin` / `rename` / `remove`，作用对象是目录接口给出的收藏文件。

`document` 供阅读区使用：返回整个文件，或某一节。它会拒绝任何不是本插件自己 `.dsh-favorites/*.md` 的路径，所以不会被当成任意文件读取接口。

每个路由都会校验 socket 地址、`Host` 头和（存在时的）`Origin` 头，与 `dsh-delete-session` 相同。

## 为什么阅读区放在面板里

DSH 在全局面板激活时一定会收起右侧栏：`shown = active && …`，而 `active = panelInfo.activePanelId === null`，`sidebar.panellist` 入口选中的正是这种全局面板。所以"收藏面板 + 会话右侧栏"两者不可能同时可见。插件因此在列表旁边自带阅读区——和官方任务页用主区分栏显示任务详情是同一个形态——顺带也就做到了浏览收藏不发生任何跳转。

## 设计取舍

- 插件不 import 任何 DSH SDK 包，也不做 DOM 注入。所有服务都在调用时通过 cordis context 解析（`ctx.get(...)`），React 和共享 UI 原语来自页面的冻结模块表，因此本包能加载到任何 profile，并在可选服务缺失时优雅降级。
- 轮次内容从会话日志（`sessionQuery`）读取，收藏下来的是持久记录，而不是转录区当时渲染出的东西。
- 收藏只记录**人说的话**。harness 的记账信息和真人的话共用同一种 `user/message` 事件——运行时快照、时间快照、指令与技能提醒、后台任务结果、子代理完成通知、队友消息——所以这里用白名单：`user`，以及定时提醒（把机器信封拆开，只保留当时写的提醒正文）。其余一律不进文件。
- harness 注入的 user 消息（runtime context、time context、instruction reminder）不会被当成你的输入；只记录来源类型不属于这些的消息。

## 限制

- 没有记录工作目录的会话无法收藏（返回 `no-workspace`），因为没有地方放文件。
- 面板只列出已注册工作区下、仍带有会话标记的文件。会话被删除后，它的 Markdown 文件会留下，插件不再展示它。
- 很长的会话会让标题调用读取会话日志；调用本身被限制在一轮文本和一次很小的模型请求内。
- 建议把 `.dsh-favorites/` 加进项目的 `.gitignore`；插件不会改动你的仓库文件。

## 开发

把 checkout 链接进 profile，让宿主半在编辑后热重载：

```sh
plugin_manager install_bundle "/绝对路径/dsh-save-chat"
```

因为此时包在 profile 目录之外，它的 Node 半默认不会被 watch。把 checkout 加进 profile 的 HMR roots（`~/.dsh/profiles/<profile>/cordis.patch.yml`）：

```yaml
- id: hmr
  name: "@deepseek-ai/dsh-hmr"
  config:
    root:
      - /绝对路径/dsh-save-chat
```
