## 1. 它和 `dsh-bookmarks` 有什么区别？

| | dsh-bookmarks | **dsh-save-chat** |
|---|---|---|
| 收藏单位 | **单条 AI 回复**（可加备注、标签） | **整轮问答**（你的问题 + 完整回答） |
| 存储 | 插件自己的存储；Markdown 是**导出**产物（`dsh-bookmarks.md`） | **每个会话一个常驻 `.md` 文件**，写在会话工作区里，Markdown 就是源；图片复制在旁边 |
| 组织 | 备注 + 标签 + 跨会话收藏中心 | 工作区→会话→条目树、可搜索、可折叠；**两层**：会话收藏 + 个人知识库（按月） |
| 模型能否读 | 无模型工具（人浏览/导出） | 注册 `search_knowledge` / `read_knowledge`，**按需**检索 |
| 依赖 | `zod` | **零运行时依赖** |

一句话：**它是"回复的批注 + 导出"，我们是"整轮问答落成文件 + 模型能按需查"。**

## 2. 和 `dsh-knowledge-base` 有什么区别？

| | dsh-knowledge-base | **dsh-save-chat** |
|---|---|---|
| 内容来源 | **导入外部文档**（md/txt/json/yml/docx/pdf，PDF 用 pdfjs-dist 解析） | **你自己的对话**，红心一键，无需导入/转换 |
| 存储 | **SQLite FTS5**（trigram + BM25），需要 Node ≥ 22.5 的 `node:sqlite` | **纯 Markdown 文件 + 附件目录**，零依赖（本包只声明 `engines.node >= 20`，与 DSH 自身一致） |
| 切块/检索 | 按标题/段落切块，短查询回落 LIKE | 段落级切块（代码围栏不切）+ BM25 + **中文二元组**；一节只出一条，矛盾时以**较晚者**为准 |
| 模型工具 | 5 个，可读写（含 import/delete） | **2 个只读**（`search_knowledge` / `read_knowledge`），默认只搜你提升过的 |
| 图片 | 未提及 | 图片复制保存 + **图片摘要**（图片能按内容被检索） |

## 3. 和 `ReMe#dsh` 有什么区别？

ReMe 是"**自动记忆**"路线：对话完成后自动批量交给 `auto_memory`，每天 `auto_dream` 把日记整理成 digest 知识，检索走 ReMe 的 Python 服务（BM25 + 可选 embedding）。dsh-save-chat 是"**人工确认**"路线：

- 只有你亲手留下的才存在（红心 / 提升进知识库）；
- 存储就是普通 Markdown 文件，**没有服务、没有数据库、零依赖**，不跑 Python 也能用检索；
- 两者**可以共存**：ReMe 管自动兜底，我们管你亲手挑的。未来计划支持把我们之外的只读 Markdown 目录（例如 ReMe 的 workspace）作为**附加检索源**，但默认关闭。

## 4. 会不会把我的对话发出去？

插件**自己不发送任何数据**：没有遥测、没有我们的服务器，只在本机读写 Markdown，接口只监听回环地址（127.0.0.1 / ::1，且校验 `Host` 与同源）。

唯一离开本机的是 **DSH 本来就在为你做的模型调用**：收藏时给这一轮起标题、提升图片时写一句图片摘要——走你自己配置的服务商。检索完全在本地，免费。

## 5. 花钱吗？

- 收藏一轮：一次小模型调用起标题（几百 token，面板里显示"已消耗 X tok"）；
- 提升图片：一次小视觉调用写摘要；
- 面板浏览、搜索、复制引用：**本地免费**。

## 6. 文件在哪？我能自己改吗？

- 会话收藏：`<会话工作目录>/.dsh-favorites/<会话标题>.md`
- 个人知识库：`~/.dsh/knowledge/<年-月>.md`（可配置）
- 都是普通 Markdown，**你可以直接用任何编辑器改**；插件会按 `mtime + size` 重新解析。

## 7. 项目删了 / 换电脑了怎么办？

收藏跟着项目走（在工作区里）；你**提升进知识库的那些不跟着项目**，`~/.dsh/knowledge/` 里的文件复制走即可，图片在同一目录的 `assets/`。

## 8. 模型能看到我全部收藏吗？

默认**只能看到你提升进知识库的部分**。原始收藏归你自己；只有当你/模型显式使用 `scope: "all"` 检索时，才会覆盖会话收藏层。

## 9. 会拖慢 DSH 吗？

解析结果按**文件大小 + mtime** 缓存，只重读变化过的文件；检索是本地 BM25，不联网。

## 10. DSH 更新后插件会不会挂？

插件是纯 ESM、**零运行时依赖**、只依赖宿主的稳定服务（sessionQuery / webServer / llm / tools / attachments），不引官方包，所以核心版本变动影响面小。仓库有 CI（21 个测试）在每次提交跑。

## 11. 怎么安装 / 怎么升级？

```sh
dsh plugin --profile web add dsh-save-chat      # 桌面 App 换成 --profile desktop
```
也可以用仓库地址或预构建包（见 README）。**DSH 目前不支持插件自动更新**——升级需要先卸载再安装新版本。

## 13. 收藏的图片会不会丢？

不会。收藏时图片会**复制**到 Markdown 旁边（`.dsh-favorites/assets/`）；提升进知识库时会**再复制一份**到 `~/.dsh/knowledge/assets/`，并在图下写一句图片摘要，这样图片之后能**按内容**被检索到。

## 被质疑时的三条原则

1. **不夸大**：只说代码里确实存在的（目录评审也会拿描述对代码，这条对社区同样适用）；
2. **不贬低同类**：把差异讲成"路线取舍"（自动 vs 人工、数据库 vs 纯文件），别写"xx 不好"；
3. **给可验证的细节**：版本号、测试数、文件路径、token 成本——具体数字比形容词可信。
